## Opening and progression

“One plan. Two possible projects.” gives the viewer a concrete question before the modelling vocabulary: would extra resources help two apparently identical 36-day plans equally?

1. **Same plan:** both full 14-task plans match at day 36. Permanent A/B cards show the different underlying rules.
2. **More resources:** double crew, tools and lift. A finishes on day 31, B on day 34. The wall/roof excerpt uses the same day 18–27 scale in every scene.
3. **Different order:** explicitly return to one resource set and prefer roof first. Both finish on day 36, but the complete plans differ.
4. **Try your own assumptions:** open the independently editable model A with a starting candidate, and focus the heading immediately before its boundary/explanation. It is not an editable two-model comparison.

Forward, previous, direct step buttons and restart are available. The full two-plan task tables, WBS, enabling-rule difference and computed JSON remain reachable through the evidence disclosure. The same pure simulator, base net and full-plan comparison are retained unchanged.

## Existing capabilities and intentional presentation changes

The editable schedule generator is presented before the manual net and theory. Resources, durations, priority, candidate count/step bound, candidates, Gantt, SMC/WBS, task table and translation contract remain available. Task durations expand separately; manual firing/random stepping/example route/reset, complete model JSON/copy and all precise method caveats remain in named disclosures. Hash links reveal their enclosing disclosures, including repeated activation of the same link.

Candidate selection uses native buttons with pressed state. Changing schedule assumptions clears prior temporary candidates with an explicit regeneration message, preventing a previous result from being labelled with new settings. Applying resources to the manual model has its own visible confirmation and direct link. The unused modal was removed after its explanation was moved into method notes.

Nothing is saved, sent or approved by the comparison or scheduler. Reload restores default values; an explicit deep link can reopen the relevant tool. Only the existing Copy JSON action writes to the browser clipboard. No run history or file-export feature is claimed.
